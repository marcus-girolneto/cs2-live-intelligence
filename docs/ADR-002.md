# ADR 002 Complete local MVP in dependency order

Accepted 2026-10-19 following user authorization to implement all phases. Target is Docker local; no cloud publication. Real Windows and user-provided demos are unavailable. Preserve gates explicitly. Day 1 baseline is committed before parallel work.

Sprint 1: Postgres/Drizzle durable users, app sessions (hashed tokens), devices (hashed credentials), one-use expiring pairing, rotation/revocation, consent/settings/deletion. Steam OpenID uses discovery-independent fixed trusted HTTPS endpoint check_authentication, expected return_to/realm, nonce age/replay prevention and claimed Steam identifier validation; actual account sign-in remains an external validation gate. Development owner/device tokens only enabled explicitly outside production. Existing Day 1 test configuration remains a memory adapter; runtime DATABASE_URL uses durable repository. Unknown endpoints return bounded errors, never fake success.

Sprint 2 starts after Sprint 1 tests: local filesystem object storage (no network/cloud required), authenticated capped .dem upload, checksum, durable jobs, Go parser subprocess with deadline/output/size limits, owner-scoped match/history. Library version pinned in Go module. A demo fixture must have lawful provenance before download. Without fixture, verify corrupt-input failure and normalized synthetic contract fixtures and report real parse unverified.

Sprint 3: deterministic @cs2/analytics consumes normalized demo contract; explicit denominators, completeness, evidence IDs. @cs2/coaching consumes evidence, validates every citation, supplies offline deterministic practice feedback and optional configured provider adapter. Provider disabled is explicit; no synthetic provider claims. Async durable Postgres jobs avoid Redis until needed. API job runner invokes parser then pure metrics/coaching modules; never in live telemetry hot path. Token/quota/retry caps enforced. GSI sessions never claim demo-complete metrics.

Sprint 4: Dockerfiles/Compose for web/API/parser-built worker and Postgres, health/readiness, structured redacted logs, counters, retention/deletion jobs, consent-based feedback/product events, documented local restore/rollback and release gates. One API replica until shared fanout exists. Public deployment and real Steam/GSI/LLM validation require external resources.

Directory ownership: backend owns apps/api including schema/migrations/auth/uploads/jobs; frontend owns apps/web; parser specialist owns apps/demo-parser. Architect owns packages/contracts additions, packages/analytics, packages/coaching, root tooling/infrastructure, collector enhancements, integration and release evidence. Existing telemetry 1.0 unchanged. Shared added platform schemas are published in packages/contracts/src/platform.ts. Parallel tasks use separate directories on shared checkout; stable Day 1 baseline commit permits isolated branches if needed. No agent changes shared contracts without architect approval.

Review revision: device rotation returns a one-use claim code bound to the same device, never a device secret to the browser. Collector claims the code privately. Logout revokes the server session and invalidates live connections. Analysis retains normalized event details, round outcomes and parser/metric provenance so citations are auditable. Missing economy data is unavailable.
