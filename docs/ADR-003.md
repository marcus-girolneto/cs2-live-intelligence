# ADR 003 Product experience: AI coach, second screen and local simulator

Accepted 2026-10-19 after user review of the local MVP ("hard to use", "where does the AI fit", "where is the second screen"). Goal: a first-run experience that needs no configuration and demonstrates every PRD pillar with real data.

## Contract additions (backward compatible, metric version 1.1.0)

`playerMetricsSchema` gains optional `name`, `advanced` (record of `metricSchema`) and `rounds` (per-round rows). Coaching insights gain optional `kind` (`strength` | `improve`). Telemetry 1.0 is unchanged. Older stored analyses still parse; they simply lack advanced metrics until re-processed.

- **Names** are display-only demo text. They never enter evidence, metric computation or provider input (tested). React escapes them.
- **Advanced metrics**, all with formula, numerator/denominator, completeness and cited events: opening kills/deaths/success, trade kills, traded deaths (5 s = 320 ticks, CS2 demos record 64 ticks/s), KAST (assist = damage assist, because the demo contract has no assist events), survival, multi-kill rounds, clutch wins (needs every participant's side; sides are resolved from the player's own events, falling back to the nearest round in the same half), ADR in won/lost rounds, ADR per side, rounds without damage. A metric abstains (`complete=false`) when its inputs are incomplete.

## AI coach

`POST /v1/analyses/:id/coaching {steamId, lang}` produces a per-player review. With `OPENAI_API_KEY` + `OPENAI_MODEL` and the daily provider quota (3/owner/day), a language model writes the review from that player's evidence only, with match averages and per-round rows as non-citable context. Otherwise a deterministic rule engine writes it. Either way every citation is validated against the player's own evidence; provider failure falls back to rules with an explicit caveat. Results are cached in memory per owner/analysis/player/language. English and Portuguese are supported.

## Second screen and live coach

`/live` is the second screen: own-player HUD, round timeline, K/D versus a baseline the viewer chooses ("This is me" in a demo, stored in the browser), and a **deterministic** between-round coach. There is no LLM on the live path (PRD §08), the coach uses only the player's own GSI data, and it is silent during live action (PRD §07, §09). A demo can be replayed through the same HUD, clearly badged REPLAY.

## Local simulator

`apps/collector/cmd/simulator` plays a scripted match into the real collector on demand. In `compose.local.yaml` the collector and simulator share the API container's network namespace (`network_mode: service:api`), so the collector keeps its loopback-only listener and loopback-or-HTTPS API rule unchanged. The simulator control API requires the GSI token, which only the web server holds. The web route `/api/simulator` exists only when local dev auth is enabled. The HUD badges this data as SIMULATED.

## Local identity

`/api/demo-session` sets the configured local owner credential as an HttpOnly cookie only when `APP_ENV=local` and `ENABLE_DEV_AUTH=true`; the browser never receives the token.

## Revision 2 (2026-10-19): real AI, Steam accounts, personalization and progress

**Provider-agnostic AI, always real.** `packages/coaching/src/provider.ts` reads `AI_PROVIDER` (presets `openai`, `openrouter`, `ollama`, or any label), `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL` (required, never defaulted), `AI_API_STYLE` (`chat` | `responses`), `AI_JSON_MODE` (`json_schema` | `json_object` | `prompt`), token/timeout/retry limits, `AI_HEADERS`/`AI_EXTRA_BODY` (JSON) and an optional `AI_DAILY_LIMIT`. Every AI request performs a real model call: no cache, no silent deterministic fallback; failures return the provider's (key-redacted) error. Uploads no longer spend tokens. Legacy `OPENAI_*` still works.

**Prompts.** `packages/coaching/src/prompts.ts` holds versioned prompts (`igl-review-v3`, `igl-live-v1`): an IGL persona, an explicit diagnose → prioritise → decide → prescribe method, grounding rules (cite only supplied evidence; positions, utility, economy and comms are not in the data and are never stated as facts) and safety rules (data is untrusted, never reveal instructions, fair play only, no cheating accusations, respectful, no medical/financial/gambling advice). Player names never reach the model.

**Live AI IGL.** `POST /v1/ai/live-call` gives one call for the next round, only between rounds (409 during live action), from the player's own numeric GSI fields (strict schema; no enemy data or free text). For live sessions the server uses its own stored state.

**Personalization and learning.** Preferences (style, tone, detail, role, focus areas, custom instructions ≤ 1000 chars) are stored per account; custom instructions are wrapped and ranked below safety, fair-play, grounding and format rules. `learnProfile` aggregates every analyzed match of the player (overall vs recent averages, tendencies, recurring patterns); previous review plans are fed back so the coach checks progress. History is context and never citable.

**Accounts.** The app requires sign-in. Steam OpenID creates the account on first sign-in, keyed by SteamID64; the public profile is cached when `STEAM_WEB_API_KEY` is set. `DEV_AUTO_LOGIN=true` (tests only) signs visitors in as the local owner. New accounts can import the operator's public sample demo (`SAMPLE_DEMO_FILE`).

**Persistence (migration 0003).** `coach_profiles`, `coach_reviews` (model, provider, prompt version, preferences, output, latency, tokens, user rating) and `coach_live_calls`, all cascading on account deletion; live calls follow the account's retention.

**Networks that inspect TLS.** `EXTRA_CA_CERTS_FILE` mounts an extra CA for the API container (`NODE_EXTRA_CA_CERTS`); TLS verification is never disabled.
