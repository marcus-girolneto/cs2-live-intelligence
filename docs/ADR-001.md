# ADR 001 Day 1 architecture and contract freeze

Accepted 2026-10-19. Day 1 is a local mock-first vertical slice. pnpm/Turbo hosts strict TypeScript Next.js and Fastify; Go collector binds IPv4 loopback. PostgreSQL compose is provisioned for Day 2; authoritative state and bounded deduplication are in one API process today. Restart loses sessions. No Redis is required.

Pipeline: mock/CS2 POST /gsi -> bounded Go queue -> POST /v1/telemetry/gsi -> reducer -> owner-scoped WS /v1/live?sessionId=... -> Next.js. GET /v1/live/sessions/:id and GET /health complete the runtime routes; GET /openapi.json documents HTTP ingest and reads.

packages/contracts/src/index.ts is the frozen authority. Envelope fields: schemaVersion 1.0, eventId, deviceId, sessionId, sequence, observedAt (provider timestamp or collector clock), receivedAt (collector clock; API overwrites with trusted arrival clock), source gsi, visibility own-player, payload. userId is resolved from provisioned device identity server-side, never trusted from telemetry. Sequence starts at 1 and increases. Collector restart uses a fresh session ID by default; explicit session ID resumes only with a persisted sequence or a new ID. Match boundary changes must start a new session or clear prior state. Snapshots are projected anew, so omitted fields become unavailable. Own stats are only exposed when player.steamid equals provider.steamid. No roster, ADR or HS inference.

Development auth uses explicit environment-provisioned device and browser credentials mapped to an owner, with a second owner in tests. No pairing or Steam claims. Browser submits its owner token via a same-origin Next.js login route that sets HttpOnly SameSite cookie; the Next.js server proxies session reads and exchanges a short-lived WS ticket at POST /v1/live/tickets. Ticket is single-use, owner/session scoped, expires in 30s. Backend accepts Authorization Bearer for HTTP reads and ticket query parameter for WS. Browser never receives a device token. Allowed browser Origin is checked by API on WS upgrade. Tickets endpoint uses owner bearer auth from the Next server.

WS messages are snapshot (state or null), diff (sessionId, sequence, changes), heartbeat (at). Diff changes contain a complete fresh projection; client replaces its state to clear omitted fields. On reconnect send snapshot. Ping/pong removes dead clients. Browser reconnects with exponential bounded backoff and a fresh ticket. Stale after 5 seconds, disconnected status immediately. Session and event stores, queue, payload and rate limits are bounded. Remote forwarding requires HTTPS, explicit HTTP exception only for loopback development.

Ownership: architect packages/contracts, packages/config, root tooling, docs, integration tests; collector apps/collector; backend apps/api; frontend apps/web. Work is isolated by directory in this new empty repository; branch/worktree separation is deferred because shared initial scaffold has no commit yet. Contracts may change only through an explicit ADR revision coordinated by orchestrator. No future-sprint implementation.
